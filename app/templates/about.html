Component roles
  • Browser: renders pages and runs small JS widgets (chat, quiz, calculator, dark mode toggle).
  • FastAPI app: a single Python process serving all routes, templates, and the ML model, bound to 127.0.0.1 only.
  • Amazon Cognito: manages user accounts and passwords, so the app never stores passwords itself.
  • Amazon DynamoDB: a single on-demand table stores dashboard events, aggregates and quiz scores.
  • Amazon Rekognition: called only when the local model's confidence is below 60%, or if it isn't trained yet.
  • Google Gemini: the chatbot's default provider, configurable via CHATBOT_PROVIDER. Falls back automatically on rate limits, network errors, or blocked responses.
  • Amazon Bedrock: the chatbot's second-choice provider (Claude Haiku) if Gemini is unavailable. A built-in rule-based assistant with 60+ topics and fuzzy matching takes over if neither is available.
  • Local MobileNetV3: fine-tuned on TrashNet, runs entirely on-device (CPU or Apple GPU), with no per-call AWS cost.

Serverless AWS deployment

This same app also runs as a serverless demo deployment (aws-deploy branch, infra/template.yaml) -- CloudFront in front of two things: the static assets in a private S3 bucket, and this whole app (unchanged, same session-cookie login) running in a Lambda function behind API Gateway. A separate, Cognito-JWT-authorized JSON API (/api/v1/classify, /uploads/presign, /waste-events, /dashboard, /quiz-score, /chat) runs as five more Lambda functions on the same API, each with its own least-privilege IAM role and no function sharing another's permissions. Its own Cognito user pool and DynamoDB table are separate from this local app's -- deployed and local data never mix.

See docs/ARCHITECTURE.md (diagram), docs/SECURITY.md (IAM rationale), and docs/COST.md (per-service estimate) in the repo for the full picture. One command deploys the whole stack (scripts/deploy.sh); one command tears it down (scripts/destroy.sh).
